# 回复候选（Tab 采纳，不自动发送）

## 使用

助手完成文字回复后，当前可见对话的输入框保持为空，默认等待 **5 秒**自动生成候选。候选以浅色文字和 `Tab ↹` 提示显示在输入区内，**不属于输入框内容**，不改变发送按钮状态，也不弹结果窗口。

- 聚焦输入框按不带修饰键的 **Tab**，才把有效候选写入输入框；发送仍需自己操作。
- 直接打字、粘贴、输入法合成、增删附件或切换会话会丢弃候选，不覆盖用户输入。Escape 也可丢弃。
- “回复草稿”可手动重新生成；旁边的设置按钮可打开自动开关和 **0–60 秒**整数延时并保存，默认开启／5秒。0秒表示满足条件后立即调度，不表示禁用。
- 设置保存在工作台 profile 设置中，通过版本校验更新。展开设置时暂停自动计时；设置不会在生成结果时自动打开。
- 只在可见页面、输入为空、会话空闲且有最后助手文字来源时计时。输入后仍非空就不生成；清空后可重新计时。页面隐藏、组件卸载取消尚未触发计时。

## 请求与费用

自动生成与手动生成都会发起一次可能收费的独立模型调用，使用**最后助手回复的来源模型**，显式 `reasoningEffort: low`。low 是低强度思考，不是关闭；模型必须声明支持low。不更改正常会话的模型／思考选择，只提取最终文字，不把 reasoning 块填入候选。最多1024输出tokens（受模型上限约束）、最长30秒、无工具，只发送上一条助手文字，不发送完整会话／附件／工具结果。

每条助手回复在当前Host进程内只自动尝试一次，成功失败都不循环重试；Host保留最近500个会话／消息组合。刷新UI不会绕过Host保护，但Host重启或旧组合被淘汰后不承诺跨进程去重。手动重试不受自动去重限制。每会话只允许一个进行中的请求，最多四个并行请求。已经发出的API调用不因关闭开关撤销计费；输入／页面变化使晚到结果不能被采纳。

草稿不是已提交的会话消息，不产生聊天轮次；底栏会话usage／费用不含这次独立调用，供应商账单可能包含。若请求审计开启，全局llm观察器可能记录独立请求；不要公开审计文件。候选可能不准确，不能代替授权、审批、选择或事实确认。

## 保护与验证

写入仅在Tab时调用宿主 `captureInsertion`／`insertText` 版本校验，不调用setDraft或发送接口。候选保存生成时的草稿版本、附件身份、来源消息、编辑器和会话身份；任一变化就失效。截断、空结果、工具调用及会话来源变化会拒绝。
