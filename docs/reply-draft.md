# 回复候选（Tab采纳／点击发送）

## 使用

助手完成文字回复后，当前可见对话的输入框保持为空，默认等待 **5 秒**自动生成候选。候选以浅色文字和 `Tab ↹` 提示显示在输入区内，**不属于输入框内容**，不改变发送按钮状态，也不弹结果窗口。

- 聚焦输入框按不带修饰键的 **Tab**，只采纳到输入框，不发送。
- 候选旁的 **发送建议** 按钮由用户显式点击后，将有效候选采纳并通过宿主原有submit流程提交。支持键盘聚焦按钮后Enter激活；不会自动连发下一条。重复激活同一候选只处理一次。候选过期、输入变化、IME、附件、新工作或切换会话会拒绝提交；失败时保留已采纳草稿并提示使用原生发送，不自动重试。
- 直接打字、粘贴、输入法合成、增删附件或切换会话会丢弃候选，不覆盖用户输入。Escape 也可丢弃。
- 输入区左侧的单一“回复建议”按钮打开设置，集中放置自动开关、**0–60 秒**延时、建议专用模型及“立即生成”。默认开启／5秒；修改后保存。0秒表示满足条件后立即调度，不表示禁用。已移除独立齿轮／箭头。
- 建议使用独立模型。空渠道／模型设置表示自动推荐已注册目录中的Luna，优先精确gpt-6-luna；也可手动选择已注册模型并保存。无可用Luna时明确提示选择，不回退到对话模型或虚构型号。不会修改正常对话选择。
- 候选存在时用组件内CSS隐藏当前输入卡片的原生提示层，候选消失立即恢复；不改原提示文字或编辑器内容。Tab标记有独立空间，不与候选末尾重叠。
- 设置保存在工作台 profile 设置中，通过版本校验更新。展开设置时暂停自动计时；设置不会在生成结果时自动打开。
- 只在可见页面、输入为空、会话空闲且有最后助手文字来源时计时。输入后仍非空就不生成；清空后可重新计时。页面隐藏、组件卸载取消尚未触发计时。

## 请求与费用

自动生成与手动生成都会发起一次可能收费的独立模型调用，使用**已选建议专用模型（默认推荐Luna）**，显式 `reasoningEffort: low`。low 是低强度思考，不是关闭；模型必须声明支持low。不更改正常会话的模型／思考选择，只提取最终文字，不把 reasoning 块填入候选。最多1024输出tokens（受模型上限约束）、最长30秒、无工具。读取最近最多6个用户轮次／12条用户与助手文字，总文字上限24000字符，最多向后扫描200条消息；最后助手回复最多16000字符，之前单条最多4000字符，截断会明确标记。不发送系统／开发者消息、思考块、工具结果、模型切换通知、含工具调用的中间助手消息或非文字附件；不会发送完整历史。用户／助手文字中本来就包含的代码或敏感信息仍可能被带入，不能视作额外脱敏。

提示词根据最近目标、已确认事项、未解决问题和下一阶段提出具体的下一步回复，避免空泛“收到，我会看看”。普通可逆界面验收可提出待用户审阅的确认＋下一步，但不得伪称用户实际测试过。涉及删除、付款、外发、权限、凭据或生产部署等敏感事项不得推断批准，应保留精确范围／影响／恢复计划的确认要求。全部候选仍须用户审阅并自行发送；提示词约束不是授权机制，也不保证每次生成质量。

reply-options只读返回contextPolicy版本2及范围，方便核对当前Host是否加载新逻辑。生成期间最近上下文发生变化（即使最后助手ID没变）会丢弃结果。

每条助手回复在当前Host进程内只自动尝试一次，成功失败都不循环重试；Host保留最近500个会话／消息组合。刷新UI不会绕过Host保护，但Host重启或旧组合被淘汰后不承诺跨进程去重。手动重试不受自动去重限制。每会话只允许一个进行中的请求，最多四个并行请求。已经发出的API调用不因关闭开关撤销计费；输入／页面变化使晚到结果不能被采纳。

草稿不是已提交的会话消息，不产生聊天轮次；底栏会话usage／费用不含这次独立调用，供应商账单可能包含。若请求审计开启，全局llm观察器可能记录独立请求；不要公开审计文件。候选可能不准确，不能代替授权、审批、选择或事实确认。

## 保护与验证

写入在Tab采纳或显式点击发送时调用宿主 `captureInsertion`／`insertText` 版本校验，不调用setDraft；仅用户显式点击“发送建议”后使用inputActions.submit。候选保存生成时的草稿版本、附件身份、来源消息、编辑器和会话身份；任一变化就失效。截断、空结果、工具调用及会话来源变化会拒绝。
